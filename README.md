# Личный трекер задач

Дашборд для человека, который ведёт несколько проектов одновременно: задачи
на день, бэклоги проектов, чеклисты к запуску, напоминания о том, кого надо
пингануть, и разбор заметок со встреч.

Собран на Next.js. Данные лежат в обычном JSON-файле рядом с кодом.

## Что умеет

- **День.** Только то, что взято на сегодня. Закрытые уезжают вниз и назавтра исчезают
- **Проекты.** Порядок задаётся перетаскиванием, у каждого проекта свои шаги и бэклог
- **Чеклисты.** Список к запуску внутри проекта, со счётчиком готовности и исполнителями
- **Пинги.** Отдельный список «жду ответа» и «написать мне», со счётчиком дней молчания
- **Разбор заметок.** Читает markdown-файлы с заметками встреч, вытаскивает задачи,
  определяет исполнителя и предлагает кандидатов на проверку, а не тащит всё подряд
- **История по дням.** Что сделано и что появилось в каждый день

Подробное описание поведения в [REQUIREMENTS.md](REQUIREMENTS.md).

## Запуск

Нужен Node.js 18 или новее.

```bash
npm install
cp data/tracker.example.json data/tracker.json
npm run dev
```

Открыть http://localhost:3000

## Где лежат данные

В `data/tracker.json`. Файл **не попадает в репозиторий**: это личные задачи,
им место на твоей машине, а не в облаке. Перед каждой записью создаётся копия
`tracker.json.bak`.

## Разбор заметок со встреч

Сканер читает папку `Work/` рядом с проектом (путь задан в `lib/scan.ts`).
Берутся только секции «Action Items», «Задачи и следующие шаги», «Действия».
Блок `Transcript` не читается никогда: в расшифровках встреч бывает личное.

## Структура

```
app/page.tsx        весь интерфейс
app/api/data        чтение и запись файла с данными
app/api/scan        разбор заметок
lib/scan.ts         правила: какие секции читать, как определять исполнителя
lib/store.ts        файловое хранилище с резервной копией
lib/types.ts        модель данных
```
